# 가영이네 공식 사이트 개발 실행 계획

2026-10-04 · 기준 코드 c3fd0a3 · 아직 구현하지 않은 실행 계획

## 목표와 개발 범위

처음 만난 손님이 모녀의 시작, 어머니를 모델로 딸이 손으로 그린 로고, 함께 가꾸는 가게를 이해하고 실제 음식과 후기를 통해 방문하고 싶어지는 사이트를 만든다. 브랜드 이야기와 #FF6600이 화면의 중심이다. 최신 PRD.md의 6개 주 메뉴, 한국어 포함 9개 언어, 기존 추천 통합을 구현한다.

이 계획은 현재 저장소의 정적 HTML/CSS/JavaScript와 Vite 개발 서버에 맞췄다. 프레임워크 전환이나 새 데이터베이스 없이 시작한다. 개발자는 파일 구조를 더 작게 나눌 수 있으나 기존 메뉴 데이터·동작·URL을 보존한다.

## 현재 코드에서 지켜야 할 사항

- 정적 출력 dist, Vercel 설정 vercel.json. npm run dev는 vite dist를 실행한다.
- 메뉴 사실: dist/data.js. 메뉴 번역: dist/menu-translations.js.
- UI 번역: dist/i18n.js, dist/i18n-extra.js. 기존 언어 en, ja, zh-Hans, vi, mn, id, fr.
- 추천 로직: dist/guide.js와 dist/data.js의 filterDishes. 기존 UI: dist/app.js.
- 기존 ?menu=M006 형식의 상세 진입 및 안내 번호 진입을 보존한다.
- 최신 재료 제외 버튼은 활성화되어 있다. 재료 취향 검색에서 contains와 possible 메뉴는 제외하고 unknown 후보에는 미포함 미확인 안내를 유지한다. 확인 사실과 dist/ingredient-guidance.js의 추정을 분리하며 unknown을 미포함으로 바꾸지 않는다.
- Tteokbokki, Gimbap, Bingsu 등 통용 음식명을 보존하며 재료·조리법은 설명에 담는다.
- 선택 버튼 우측 상단 체크를 다시 추가하지 않는다. 오렌지 테두리·배경과 aria-pressed를 사용한다.
- 본문 18px, 보조 안내·버튼 최소 16px, 원본 사진 contain, 가로 스크롤 없음.
- 기존 7개 언어 메뉴와 공식 사이트 9개 언어는 범위가 다르다. 기존 프랑스어 URL과 화면을 삭제하지 않는다.

## 구현 구조 제안

기존 루트 메뉴를 유지하면서 dist/official/에 공식 사이트를 추가한다. 초기 개발 주소는 /official/?lang=ko&view=home 형식이다. view는 home, story, menu, recommend, prepay, visit 여섯 개로 구성한다. 정적 환경에서 직접 열기·새로고침이 가능하고 별도 서버 라우터가 필요 없다.

공식 도메인 루트 연결은 공개 단계에서 호스팅과 URL 이관표를 확인한 후 적용한다. 현재 추천 도메인은 후보이며 구매 또는 연결 완료 상태가 아니다.

예정 파일:
- dist/official/index.html: 공통 문서, 헤더, 접근성 진입점.
- dist/official/app.js: 라우팅과 화면 조립.
- dist/official/site.css: #FF6600 토큰, 반응형 레이아웃, 타이포그래피.
- dist/official/content.js: 승인된 브랜드·로고·고객 이야기, 출처와 게시 상태.
- dist/official/locales/*.js: 9개 언어의 UI와 브랜드 콘텐츠.
- dist/official/menu-adapter.js: 기존 메뉴 사실을 읽고 필요한 ko/th/ru 등 번역을 결합.
- dist/official/components/: 공통 헤더·언어선택·사진·고객 이야기·메뉴 UI 등 필요한 단위.
- dist/official/assets/: 확인된 추가 브랜드 원본과 폰트만 보관.
- docs/official-site/VERIFICATION.md: 실제 검사 결과와 남은 공개 조건.

기존 가격·재료를 새 파일에 복사해 별도 사실 원본으로 만들지 않는다. 메뉴 어댑터는 기존 데이터에서 파생하며 화면용 번역·사진 URL 정규화만 담당한다. 기존 ./assets/... 사진 경로는 공식 페이지의 중첩 경로에서도 올바르게 해석되도록 한다. 상태를 바꾸면서 기존 전역 메뉴 레코드를 변형하지 않는다.

## 1단계 기준 확인과 실행 준비

1. AGENTS.md, 이 폴더 README.md, PRD.md, ASSETS-AND-GATES.md를 읽는다.
2. 원격 변경을 fetch하고 최신 변경과 이 계획을 비교한다. 기존 사용자 변경을 되돌리지 않는다.
3. 인수인계 브랜치를 기준으로 구현 작업 브랜치를 만든다.
4. package-lock.json 기준 npm ci 후 npm test로 시작 상태를 기록한다.
5. dist/official/ 존재 여부를 확인하고 기존 작업이 있으면 보존한다.

완료 조건: 현재 테스트 결과, 기존 링크와 메뉴 수, 실제 파일 경로를 기록했다. 실패는 환경 문제와 기존 제품 문제를 구분한다.

## 2단계 공식 사이트 골격과 한국어 홈

1. dist/official/에 화면과 공통 탐색을 추가한다.
2. 홈 순서는 PRD 3장을 따른다. 중심 문장과 실제 로고·사진, 모녀의 시작, 로고 이야기, 함께 운영하는 모습, 캐릭터, 대표 음식, 고객 이야기, 방문 초대가 이어진다.
3. 첫 화면은 브랜드 이야기로 진입하는 주 버튼과 메뉴 보기 보조 버튼을 제공한다.
4. 기본 배경 #FFFDFB·크림 #FFF5E9에 #FF6600을 사용한다. 긴 본문은 짙은 글자색으로 읽게 한다.
5. 승인된 실제 로고·음식 사진부터 연결한다. 확보하지 못한 인물·캐릭터 이미지를 생성해 대신 넣지 않는다.

완료 조건: 390px와 1280px에서 한국어 홈과 브랜드 이야기의 실제 화면을 확인할 수 있다. 고객 후기와 메뉴 기능이 완성되지 않아도 그 상태를 미리보기 검토 기록에 명시한다.

## 3단계 브랜드 이야기와 자산 연결

1. 로고의 모델은 어머니, 직접 그린 사람은 딸 가영, 오픈 준비 당시 수작업이라는 사실을 구분한다.
2. 2012년 어머니의 경력 시작, 2022년 가영이네 개점, 2024년 확장을 세로 이야기로 구성한다.
3. 말랑가영이·토끼는 확보한 승인 원본만 연결한다. 원본 부재 시 텍스트 소개까지 개발하고 자산 필요 상태를 기록한다.
4. 세 벤치마크의 디자인 원리는 PRD 10장을 따른다. 참고 사이트 사진·캐릭터·문구를 사이트 자산으로 복제하지 않는다.
5. 폰트 파일 및 라이선스가 확인되지 않으면 언어별 시스템 대체 글꼴로 개발하고 최종 적용을 추적한다.
6. PRD 10장의 추가 승인 기준을 적용한다. 셀렉토가 전체 레이아웃·타이포그래피의 주 기준, 불닭이 캐릭터·상호작용의 참고다.
7. 첫 화면/이야기 등장, 캐릭터 반응, 로고 옆 장식선, 버튼·카드 반응을 구현한다. 승인 원본의 분리 여부를 확인하고 가능한 모션부터 적용한다. 축소 동작·정지 상태에서도 모든 콘텐츠를 제공한다.
8. 오렌지 라인 떡꼬치 커서를 제작하고 정밀 포인터에서만 적용한다. 클릭 지점·대비·입력 영역 기본 커서·터치 비노출을 검증한다. 커서 및 모션 자산은 아직 제작 전이다.

완료 조건: 제안 카피·실제 사실·고객 원문이 구분되고, 이미지 원본 비율과 모바일 가독성이 유지된다.

## 4단계 다국어와 메뉴 추천 통합

1. 한국어 기본, 외국어 순서 en → zh-Hans → ja → vi → mn → th → ru → id를 적용한다.
2. URL 언어 → 저장한 선택 → 한국어 순서를 적용한다. URL에 언어를 반영하고 history 탐색·새로고침을 처리한다.
3. 제목·본문·버튼·안내·오류·대체 텍스트·후기 편집문을 9개 언어로 제공한다. 한국어 메뉴명 병기와 원문 보기의 원문 언어는 예외로 명시한다.
4. 기존 메뉴 사실과 추천 함수를 재사용한다. 메뉴 32개와 가격·맵기·추천 기준을 임의 변경하지 않는다.
5. 메뉴와 추천에서 같은 데이터를 읽고, 조건 선택 후 언어를 바꿔도 선택이 유지되게 한다.
6. 미확인 후보의 확인 필요 안내와 직원 문의를 제공한다. 결과가 비면 조건 재선택을 안내한다. 음식명을 sushi 등 다른 음식으로 바꾸지 않는다.
7. 기존 프랑스어 메뉴는 기존 루트에서 계속 이용할 수 있게 한다.

완료 조건: 모든 공식 화면의 9개 언어 키가 완비되고, 공유 URL과 언어 변경 후 필터·화면 상태가 보존된다. 번역 초안 완비와 원어민 검수 완료는 별도 상태다.

## 5단계 고객 이야기와 방문 및 선결제 안내

1. PRD의 실제 후기 기반 초안 2건을 출처·작성일과 함께 연결한다.
2. 외국인 고객 후기 최소 1건은 원문과 방문자 맥락을 확인한 뒤 편집한다. 언어만으로 국적을 추측하지 않는다.
3. 후기 사진과 매장 메뉴 참고 사진을 구분하고 확인되지 않은 자료는 미게시 상태로 둔다.
4. 매장 주소와 지도는 dist/store-links.js 및 승인 데이터로 연결한다. 전화는 0507-1477-2825, tel:050714772825.
5. 선결제 서비스의 실제 URL·필드·접수 상태를 먼저 확인한다. 찾지 못하면 거짓 신청 폼이나 결제 완료를 만들지 않는다. 안내 화면과 방문·전화 연결까지 준비한다.
6. 서비스가 확인되면 기존 신청 흐름을 재사용한다. 신청 접수와 결제 완료를 분리한다.

완료 조건: 출처 연결이 있고, 필수 외국인 후기 확보 여부가 기록되어 있다. 선결제 연결 미확인을 구현 완료로 계산하지 않는다.

필수 검사:
- 기존 npm test 회귀 검사 및 변경한 JavaScript 구문 검사.
- 신규 공식 사이트의 언어 누락, URL 복원, 메뉴 데이터 일관성, contains·possible 제외 및 unknown 안내 유지, 실패 안내를 검증하는 의미 있는 테스트.
- 실제 브라우저 320·390·820·1280px에서 홈·이야기·메뉴·추천·선결제·방문 흐름 확인.

- 떡꼬치 커서의 실제 클릭 위치, 밝은/오렌지 배경 대비, 입력·선택 기본 커서, 터치 비노출 확인. 자동 반복 장식 정지, 정적 상태의 전체 내용 접근 및 원본 로고 보존 확인.
- 기존 ?menu=M006, 안내 번호 링크, QR 목적지 및 프랑스어 경로 보존 확인.

기존 검사 명령:
```sh
npm ci
npm test
npm run dev
```

npm run dev 출력의 로컬 주소에 /official/을 붙여 개발 화면을 연다. 실제 명령 출력 주소를 사용하며 위 경로는 구현 후에만 존재한다. 새 테스트 명령은 구현자가 추가한 뒤 문서에 기록한다.

각 기능 단위로 검증하고 커밋한다. 마지막에는 실제 검사 명령·성공/실패·화면 캡처·미확인 자료를 VERIFICATION.md에 기록하고, 변경 설명과 함께 검토 가능한 작업 브랜치 또는 PR을 제공한다. 배포 성공과 실제 URL 확인 없이 사이트 공개 완료라고 보고하지 않는다.

## 공개 준비와 이번 인수인계의 경계

이번 작업은 개발 문서 준비와 GitHub 저장이다. 실제 사이트 구현, 도메인 구매, 본 사이트 전환을 완료한 것이 아니다.

코덱스는 문서에 따라 개발 미리보기까지 진행할 수 있다. 외국인 후기 원문, 공식 캐릭터·폰트, 핵심 사진, 선결제 연결, 번역 검수, 실제 도메인 등록과 연결은 ASSETS-AND-GATES.md에 근거와 상태를 남긴다. 개발과 자료 확인을 구분하며, 미확인 필수 항목을 임의 사실로 채워 공개하지 않는다.
